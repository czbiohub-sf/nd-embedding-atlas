## [unreleased]

### 🚀 Features

- _(server)_ [**breaking**] Harness edits are proposals by default. MCP `edit_dashboard` validates the whole batch and returns `{ status: "proposed", id, changes: [{ index, summary }] }`: its `set_filter` ops apply at once, the rest wait in the server's memory (a restart drops them) until the person accepts or rejects each change. Accepting re-runs the chosen changes on the current revision and commits them as one revision stamped with the proposing agent; a change that no longer applies becomes `invalid` with its reason while the others commit. New MCP tool `get_proposal` reports each change's status; `patch_workspace` and `restore_revision` are refused until the mode is `direct` (Apply directly), which restores immediate edits. Every MCP tool call lands in a 50-entry tool-call feed (arguments in a few words, outcome such as `proposed 2 changes` or `→ 7,688 obs`). `/ws harness/watch` now pushes `{ kind: "state", state }` (agents, mode, pending proposals, feed) and `{ kind: "rejected", agent, reason, issues }` per invalid harness edit instead of the agent list; REST `GET /api/harness`, `PUT /api/harness/mode`, `POST /api/proposals/:id/accept` and `/reject` (optional `{ changes }`). Contract in `@ndea/protocol` (`harness.ts`); `HarnessPresence` is gone.
- _(frontend)_ Proposal review. While the harness has pending proposals, a tile it proposes shows in the grid as a ghost tile (dashed `--primary` outline, "Proposed · <title>", the agent, Accept / Reject, no live body); every other change (props, removals, sources with a before → after diff of the source, links, layouts) is listed in a bar at the bottom centre ("<agent> proposes N changes", Accept all / Reject all / Review) and in the Harness flyout, never previewed in the grid. A change that no longer applies toasts its reason. An edit the workspace rejected shows once as a toast (agent, reason, first issue) and the Harness rail button shakes. The Harness flyout adds pending proposals and the tool-call feed (time, tool, arguments, outcome; writes in `--primary`); Settings gains Harness edits (Propose | Apply directly). The rail's harness presence now reads the `harness/watch` state.
- _(data)_ Collections. A project YAML may group its datasets with `collections:` (a list of `{ name, datasets }` or a name-keyed map; a dataset may be in several; datasets in none form an implicit collection named after the file, so a file without `collections:` is one collection). `ndea view --collection <name>` opens one (default: the first) and ingests only its datasets. The Data flyout lists collections › datasets with obs counts: the open collection's datasets are include toggles over the `_dataset` filter (scope `A`, source `dataset`; one = `eq`, several = `in`, all = cleared), another collection has a Switch action. ⌘K's Datasets group becomes Collections (open collection's datasets filter, another collection switches). Switching asks for confirmation, then `POST /api/collection` clears the dataset filter, re-ingests in-process on the same port, and every tab reloads (`session/watch`); the workspace file stays the same. `/data/metadata.json` and `/api/status` report `collection` and `collections`; MCP gains `list_collections`.
- _(frontend)_ [**breaking**] Named layouts and tabs (workspace format v3). The document is `{ data, layouts: { [id]: { name, spec } }, layout, state }`: element ids are unique across layouts, `data` and `state` are shared, and the active layout is stored in the document. Any other format version (every v2 file) is refused at startup with a message naming the file; delete it to reseed from the preset. A `tabs` component holds a tile's views (`active` = the shown one; a bare view stays a one-tab tile): the tile header shows every tab, **+** adds one from the empty-tile list, × closes one (the last leaves an empty tile), and dragging a tab onto another tile's tab strip moves it without remounting its body (onto a tile body still swaps tiles). Inactive tabs start on first show and stay alive; views outside the active layout stop until it is shown again. The Layouts flyout lists every layout (wireframe, "current"), switches on click, adds from a template (blank or a copy of any layout), and duplicates, renames (inline) and deletes (with a confirm) the current one; ⌘K lists every layout and its preview follows the highlighted row. New `edit_dashboard` ops `add_layout`, `rename_layout`, `remove_layout`, `set_active_layout`, `add_tab`, `move_tab`, `close_tab`, `set_active_tab`; `add` takes `layout`; element ops, `get_result` and `/api/workspace/elements/:id` search every layout. The `exploration` preset has two layouts: Exploration (Table and Histogram tabs at the bottom) and Review.
- _(data)_ DuckDB 2.0. Every dependency is on its latest release; `@duckdb/node-api` 2.0.0-r.1 ships DuckDB 2.0.0. The duckdb-zarr extension builds against duckdb-rs `1.20000` and loads through the stable C API (DuckDB 2 accepts unstable-ABI extensions only through a v2 entrypoint duckdb-zarr does not have yet), and the static darwin-arm64 `duckdb.node` links the release's `duckdb-static-libs-osx-arm64.tar.gz`. Ingest caches from DuckDB 1.x are rebuilt on first open.
- _(table)_ The table is the field editor and replaces the separate annotation component, which is gone. Toolbar: search (server-side, across text fields), `Filter │ Sort │ Group │ Fields` (a filter builder publishing typed clauses on the table's `filter` facet; sort on `ordering`; group by one category, label or boolean field with collapsible headers and obs counts from a `GROUP BY` query; field visibility and order in the `columns` prop, grouping in `groupBy`), Save / Discard for unsaved edits, and "Write fields to file…" (dry run, then confirm). Headers show a type glyph and provenance (saved field ●, unsaved ring in `--dirty`; Settings › Provenance badges, a per-browser preference); a header menu sorts, groups, hides, and renames / converts (label ↔ text) / deletes fields; **+** adds a label or text field. Label and text cells edit inline into a client buffer (edited cells get an amber bar) that Save posts through `/api/annotations/values`. Click focuses an obs; shift-click selects a range, ⌘-click toggles, the header checkbox selects every listed obs; the selection publishes `{op:"inSet"}` on the `selection` facet. Annotation fields are `label` or `text` (integer/float fields, predicate writes, `/api/annotations/save`, `/api/annotations/export` and the 2s autosave are gone): `PATCH /api/annotations/columns/:name` renames or converts, values rows are `{rowIndex, value}` (the server fills in obs identity), and every field write saves the Parquet sidecar before it responds. The default preset is `exploration`: embedding, image viewer and crop gallery above a table, on filter A and focus A.
- _(frontend)_ View tiles gain a link indicator (one dot per link) whose popover lists each link's value and member views with Unlink (hovering a row highlights the members; the Links flyout can unlink too), a view settings gear (editable title; Display / Data / Links tabs generated from each component's config schema through new Zod field metadata; footer with copy reference, fullscreen, duplicate, remove), and copy reference: `ndea://<workspace>/<element-id>`, which MCP `get_result`, `create_observation_set` and `edit_dashboard` accept wherever they take an element id. `GET /api/workspace` returns the workspace `name`. Agent edit ops moved to `core/workspace/edits.ts` and are shared with `WorkspaceStore.apply`. `@ndea/ui` gains `Switch`.
- _(frontend)_ ⌘K command menu replaces the theme-only palette: a centered 760px window that switches the layout (mini wireframe, "current", and a preview with tile titles) and the dataset (a tree under "All datasets" with obs counts; picking one filters every scope-`A` view to that dataset through a `_dataset` clause under source `dataset`, "All datasets" clears it; → / ← expand and collapse). Typing `>` lists commands: light / dark theme, toggle sidebar, open each flyout, and, for the selected tile, fullscreen, copy reference, split left / right / up / down, remove, plus "Add <component> to the first empty tile". The read-only recovery page keeps ⌘K with the theme commands. Mini wireframe cells use `--accent`, so they show in light theme too.
- _(image-viewer)_ A Channels button opens the channel panel (visibility, named colormaps, contrast limits over a log histogram of the channel stats, auto contrast); a View button holds T/Z, 2D/3D, the focus box, volume settings, and local/remote rendering; a scale bar in the OME-Zarr axis unit sits bottom-right; the focus box is drawn in `--focus-mark`.
- _(scatter)_ Embedding controls. The docked toolbar strip is gone: a floating group top-left inside the view holds pointer / box / lasso (V, B, L on the hovered or last-used view; shift adds, ⌥ subtracts) and Legend (color by, palette or colormap, density, pin), Point size (size, trajectory) and Axes (2D/3D, z, projection, selection depth, Fit view) popovers. A bottom-right axis picker (`x UMAP1 │ y UMAP2 │ swap`, wheel steps dimensions) writes the new `xDim`/`yDim` props; `pointSize` and `legend` (`popover` | `pinned`) persist too, and the component is titled "Embedding". After a selection a top-centre pill shows the exact obs count with Invert, Save as source (a `Selection-<n>` data source via the new `host.dataAPI.saveSource`) and Clear (or Esc). Component notifications now show as toasts.
- _(server)_ [**breaking**] One column catalog. `GET /api/columns` returns the `dataset` VIEW's columns as `[{ name, type, sqlType, kind }]` (`type`: string | number | boolean | other; `kind`: obs | var | annotation; internal `__*` columns left out). Table fields and provenance, chart and vgplot field pickers, and scatter color-by lists read it (`useColumns` / `fetchColumns` in `@ndea/components/query`) instead of running `DESCRIBE dataset` or reading `metadata.obs_columns`, and refetch after a field operation, so a new field shows in every view without a reload; those lists now include `obs_name`, `_dataset`, and `_index`. A row selection becomes a filter through one host call, `host.filter.publishSelection(facet, bits, rows, signal?)` (creates the observation set, publishes `{ op: "inSet" }`, clears on `null`), replacing `host.dataAPI.createObservationSet`; `host.dataAPI.query` is gone (Count queries through the coordinator). `quoteIdent` lives in `@ndea/protocol`.

- _(data)_ AnnData and MuData are read by DuckDB through the [duckdb-zarr](https://github.com/xqlsystems/duckdb-zarr) extension (v0.2.0, built from source for the installed DuckDB and embedded in the binary; `LOAD` reads the extracted file, no network). `obs_base`/`var_base` come from one SQL path for single stores, unions, and MuData; opening a dataset reads metadata only. On 10M synthetic obs: cold start 36 s → 16 s at 3.4 GB peak RSS instead of 9.2 GB, warm start 5.0 s → 0.22 s (opening reads no column data), and a CSR gene column 3.7 s instead of not finishing in 10 minutes. Bool and nullable-int columns are BOOLEAN and INTEGER for unions and MuData too, MuData ingests are cached, and a column named after its axis reads as `obs/obs`. Building from a checkout now needs Rust (`vp run build:zarr-ext`); every DuckDB upgrade rebuilds the extension. `ndea self doctor` reports it.
- _(image-viewer)_ Remote rendering. An image viewer's new `render` prop (`"local"` | `"remote"`, settable through `edit_dashboard`) renders it in a headless Chrome that ndea launches on the server's machine, driven over a CDP pipe, and streams the canvas as H.264 (VP9 fallback) WebCodecs chunks over `/ws/render` to the tile, which decodes them and sends pointer and wheel input back. The same viewer controls (channels, contrast, T, Z, bbox) work on the stream. One SSH tunnel is enough on HPC; `ndea self doctor` reports the Chrome, WebGL renderer, and encoder it would use. Caps: `NDEA_RENDER_SESSIONS`, `NDEA_RENDER_MAX_PIXELS`, `NDEA_RENDER_FPS`, `NDEA_RENDER_BPP`; Chrome from `NDEA_CHROME` or the usual install paths.
- _(scatter)_ Research-backed scatter rendering. Points are stored in Morton order in 256-point batches with bounding boxes, so compaction, the density splat, and selection skip off-screen batches, and the splat sums each batch in workgroup memory before touching the grid (10M fit frame ~1.15 ms GPU instead of ~1.56 at full clocks; zoomed ~0.44 vs ~0.70). Lassos, filters, and picks still speak row ids. A new `density` prop (`{ mode: "mean" | "dominant" | "weave" }`, also a toolbar toggle next to the color picker) composites overlapping categories as their average color, the dominant category, or woven by share. 3D lassos and marquees get a `through`/`front` toggle: `front` selects only the nearest dense structure under the shape. Big lassos publish ~5× faster: DuckDB builds the observation set (5M rows: ~0.4 s instead of ~2.2 s) with unchanged set ids.
- _(scatter)_ 3D scatter plots. An embedding with three or more columns gets a `3d` toggle and a Z dimension picker in the Scatter toolbar; the element's new `zDim` prop (also settable by agents through `edit_dashboard`) persists it. Drag orbits, right- or Ctrl/Cmd-drag pans, the wheel dollies toward the cursor, `persp`/`ortho` switches the projection, and Fit view frames the data. Zoomed-in views draw opaque depth-tested discs; overviews use the density path. Lasso and marquee select everything that projects inside the shape, occluded points included; a click focuses the front-most point. `viewSync` cells gain optional `yaw`, `pitch`, `distance`, `target`, and `projection`: 3D scatters on one scope orbit together and 2D views ignore 3D cells. `/api/scatter-positions` takes an optional `z_col` (400 when the embedding lacks that column) and now returns position columns (x, then y, then z) instead of interleaved pairs. Trajectories (Track) draw on the GPU in the points' render pass, in 2D and 3D: anti-aliased round-capped segments that fade from early to late, a dot per frame in its category color, and a white active-t marker. In 3D they are depth-tested against the discs, and the active marker shows dimmed through whatever hides it. Positions come from the scatter's own columns by row, so `/api/trajectory` drops its `embedding`, `x_col`, and `y_col` params and the `emb_x`/`emb_y` frame fields, and the SVG overlay (with its arrowheads and start/end markers) is gone.
- _(scatter)_ Faster scatter at scale. Lassos and filters move as row bitmasks (`/api/sets` accepts a binary bitmask; no 5M-row cap), the lasso readback no longer reports a stale selection, and a new TypeGPU render core (one camera matrix, SoA buffers at ~15 B/point instead of 64, compaction + indirect draws, a density splat when too many points are visible, GPU id picking) draws a 10M-point fit view in ~3–4 ms of GPU time instead of ~41 ms. In density mode the compaction pass only estimates the visible count.

The command shown is `ndea self update`, or `mise upgrade …` for mise installs. The docs site publishes the latest release at `registry/ndea`; the Release workflow redeploys it.

Design tokens (Pierre Dark neutrals, Biohub teal accent, Geist + Geist Mono, the 3.5–9.8px radius scale, 140/180/260ms motion) live in `@ndea/ui`; dark is the default; every pop-up shares one frame; tooltips wait 500ms; toasts are restyled; glass/blur chrome and native `<select>`s are gone. ### 🐛 Bug Fixes

- _(server)_ Gene columns from a sparse (CSR/CSC) `X` held the stored values in the first rows and NULL elsewhere; they now have each value at its row and 0 where nothing is stored. Gene and annotation values are exact (no SQL literal rounding), and ingest appends whole data chunks instead of rows.
- Wire CLI startup to createApp, fix DuckDB ingestion
- Metadata props.data schema, dev script, frontend scripts cleanup
- _(frontend)_ Fall back to first available obsm key when none loaded
- _(frontend)_ Format non-scalar table values without implicit object stringification
- _(server)_ Return DuckDB BIGINTs as JS numbers when safe
- _(frontend)_ Clear ExportDialog setInterval on unmount
- _(frontend)_ Clear useVarColumn poll interval on unmount
- _(frontend)_ Abort in-flight embedding load on unmount
- _(build)_ Keep embedded frontend and DuckDB source manifests as stable development stubs
- _(server)_ `PATCH /api/workspace` and MCP writes now reject a document whose typed clauses (a data source's `where`, a `state.filter` clause) name a column the dataset lacks, with a JSON-pointer issue per clause (e.g. `/data/bad/where/column`); raw `data.sql` is still checked only when it runs. Startup logs the same issues for the workspace file instead of refusing it.
- _(frontend)_ The table's rows stayed blank after a filter change that also moved the focused obs: the reveal scrolled before the list had its new height, so the scroll was lost while the virtualizer drew the target rows. The reveal now waits for the rendered height.
- _(frontend)_ Embedding wheel zoom applies at once about the cursor. It used to glide toward a target (6% per frame, so its speed followed the frame rate) with a magnetic stop near the home zoom, and a click mid-glide jumped to the glide's end. Fit view is the one remaining animation; a press stops it where it is. The unused `lerpSpeed`, `lerpEpsilon`, and `zoomSensitivity` interaction options are gone.
- _(frontend)_ A scrolled table (or gallery) went blank after its tile re-rendered, switched tabs, or went fullscreen: re-attaching a view's body resets the scroll offsets inside it without a scroll event, and the virtualizer kept drawing rows at the old offset, off-screen. A body socket now adopts only when the body is elsewhere and carries the offsets across the move, and the virtualizer re-reads the offset when its scroller is laid out again.
- _(frontend)_ Clearing an embedding selection (Esc) after focusing a point threw the table to an unrelated row: the table re-applied its last "reveal the focused row" scroll whenever its height changed, long after the focus, at an index from the old, smaller list. A reveal now applies once.
- _(ui)_ Higher-contrast chrome. Muted text and icons are `#c8c8c8` in dark (was `#a3a3a3`) and graphite in light (was dark slate); faint text is `#8a8a8a` / dark slate, which now passes WCAG AA (it was ~3.2:1 in dark). Icon strokes are 1.75 px (were 1.5) in icon buttons, `nd-icons`, and tile chrome.

This page lists the supported `ndea` commands, flags, and release channels.

Walkthroughs live in [Getting started](/). Dev-side commands (`vp run dev`, `vp run build`, …) live in [Contributing](/contributing).

## Synopsis

```
ndea [paths...]                                  # default; equivalent to `ndea view`
ndea view [paths...] [options]
ndea status [--json] [--host <host>] [--port <port>]
ndea workspace get [--host <host>] [--port <port>]
ndea workspace patch --revision <n> --ops <json> [--host <host>] [--port <port>]
ndea workspace history [--limit <n>] [--host <host>] [--port <port>]
ndea workspace restore <revision> [--base <n>] [--host <host>] [--port <port>]
ndea workspace result <element> | --data <name> [--host <host>] [--port <port>]
ndea workspace query [--where <json>] [--limit <n>] [--host <host>] [--port <port>]
ndea mcp install | check | uninstall [options]
ndea self update [options]
ndea self doctor [--check-network] [--strict]
ndea self prune [--keep <n>]
ndea completion <bash|zsh|fish>
ndea man
ndea --help | --version | --no-color
```

Every command accepts `--no-color` (and `--color`); `NO_COLOR` and `FORCE_COLOR` work as usual. Output is plain when stdout is not a terminal, so pipes, CI logs, and agents see no escape codes or spinners.

## Shorthand

`ndea path/to/data.zarr` is equivalent to `ndea view path/to/data.zarr`.

## `ndea view`

Open one or more Zarr stores, or a YAML project config, in ndea.

### Arguments

| Name     | Type              | Description                                 |
| -------- | ----------------- | ------------------------------------------- |
| `paths…` | one or more paths | Zarr stores or a single YAML project config |

A single `.yaml` / `.yml` path is parsed as a multi-dataset project config (see [Project YAML](/project-config)).

### Options

| Option                 | Type    | Default     | Description                                                                           |
| ---------------------- | ------- | ----------- | ------------------------------------------------------------------------------------- |
| `--port <port>`        | integer | `5055`      | TCP port for the local server                                                         |
| `--host <host>`        | string  | `127.0.0.1` | Hostname to bind                                                                      |
| `--no-open`            | boolean | `false`     | Do not auto-open the browser                                                          |
| `--no-tui`             | boolean | `false`     | Keep log output instead of the live status screen (a non-terminal stdout always does) |
| `--no-static`          | boolean | `false`     | Do not serve the bundled frontend (Vite serves it in dev mode)                        |
| `--obs-columns <list>` | string  | all columns | Comma-separated subset of obs columns to load                                         |
| `--preset <name>`      | string  | `exploration` | Preset a new workspace file starts from: `exploration` or a `.json` workspace document |
| `--workspace <file>`   | path    | see below   | Workspace document to open and save                                                   |
| `--collection <name>`  | string  | the first   | Collection of a YAML project to open ([collections](/project-config#collections))     |

### Workspace file

The running server owns one workspace document: named data sources, named layouts (each a dashboard spec; one is active), and coordination state. Every edit, from the browser or from `ndea workspace patch`, is saved to the workspace file as a new revision. Without `--workspace`, ndea uses `~/.ndea/workspaces/<key>.json`, where the key is derived from the dataset paths, so opening the same datasets reopens the same workspace. A missing file is written from the preset as revision 1, before any browser opens. A preset is itself a workspace document: `--preset exploration` uses the built-in one (two layouts, Exploration and Review), and `--preset my-layout.json` copies any valid document, such as the `document` field printed by `ndea workspace get`. A file or preset that fails validation stops `ndea view` before any data loads and lists each problem by JSON Pointer; ndea never rewrites or migrates it. A workspace file of another format version (files written before format 3) is refused the same way; delete it and the preset seeds a new one.

`--port` accepts integers in `[1, 65535]`.

### Trust model

ndea trusts everyone who can reach its port. It binds `127.0.0.1` by default; to use a server on another machine, forward the port over SSH (`ssh -L 5055:127.0.0.1:5055 <host>`). The dashboard, its data and query routes, `/ws`, `/ws/render`, and `/plate/*` have no authentication. `/mcp` accepts only loopback `Host` and `Origin` headers plus the bearer token in `~/.ndea/mcp-token`, and `GET /api/status` and the dataset structure route need that token because they show file paths. A non-loopback `--host` prints a warning at startup and adds no authentication, so bind one only on a network you trust.

## `ndea self update`

Download and activate the latest release for a channel. ndea verifies the SHA-256 checksum before switching versions.

Not available on Windows. Windows installs are a single `ndea.exe` with no versions tree and no symlink to swap, so the command exits with an error; re-run `install.ps1` to move to a newer release.

### Options

| Option                | Type                                  | Default  | Description                                               |
| --------------------- | ------------------------------------- | -------- | --------------------------------------------------------- |
| `--channel <channel>` | `stable` \| `latest` \| `pre-release` | `stable` | Release channel to resolve                                |
| `--force`             | boolean                               | `false`  | Re-install even when already on the target                |
| `--no-gc`             | boolean                               | `false`  | Skip the post-update prune that removes inactive versions |

For standalone installs, a successful update keeps only the active version by default. Pass `--no-gc` to retain inactive versions, then prune them later with `ndea self prune`.

For mise-managed installs, `ndea self update` updates the active mise config through mise and does not write to `~/.ndea/versions`. `--no-gc` has no effect because mise owns version retention.

A running `ndea view` session continues using the version it started with.

Installed binaries check once a day, after a command finishes, whether a newer stable release is out, and print an "Update available" notice to stderr with the command to run. Each version is announced once. The check reads `https://czbiohub-sf.github.io/nd-embedding-atlas/registry/ndea` and keeps its state in `~/.local/state/ndea/update-notifier.json`; offline, it stays silent. Under the status screen the notice goes to the Logs tab and prints after you quit.

To install a specific older standalone release, uninstall the current standalone installation, then pass its tag to the installer:

```bash
rm -f "$HOME/.local/bin/ndea"
rm -rf "$HOME/.ndea"
curl -fsSL https://czbiohub-sf.github.io/nd-embedding-atlas/install.sh | sh -s -- v0.1.0
```

On Windows, pass the tag to the installer; it replaces `ndea.exe` in place, so no removal step is needed:

```powershell
& ([scriptblock]::Create((irm https://czbiohub-sf.github.io/nd-embedding-atlas/install.ps1))) -Version v0.1.0
```

For mise-managed installs, select a version explicitly:

```bash
mise use -g --pin github:czbiohub-sf/nd-embedding-atlas@0.1.0
```

## `ndea self prune`

Prune old installed versions. ndea always preserves the active version.

### Options

| Option       | Type    | Default | Description                                       |
| ------------ | ------- | ------- | ------------------------------------------------- |
| `--keep <N>` | integer | `1`     | Number of versions to keep (active counts; min 1) |

## `ndea self doctor`

Diagnose the install. Prints binary path, symlink integrity, whether the embedded duckdb-zarr extension loads (and its version), active version, installed versions with disk usage. Exit code 0 if healthy, 1 on hard anomalies (broken symlink, missing active binary).

On Windows the symlink and installed-versions sections are omitted, because that layout has neither. Everything else, including the extracted-library cache check, reports normally.

### Options

| Option            | Type    | Default | Description                                                           |
| ----------------- | ------- | ------- | --------------------------------------------------------------------- |
| `--check-network` | boolean | `false` | Probe GitHub Releases API reachability over the network (3 s timeout) |
| `--strict`        | boolean | `false` | Treat warnings as errors (non-zero exit)                              |

## `ndea status`

Show a running server's live status. The header carries the version, URL, uptime, memory, and whether DuckDB came from the ingest cache. Three tabs follow (Tab or 1-3 switches):

- **Overview**: one card per dataset with its format (AnnData or MuData, with modalities), observations × variables, obs column count, its embeddings (green ready, amber loading, red failed), the plate's well count and channels in their colors, and its path and size on disk (`…` until the background measurement finishes); then the workspace file with its revision and last change (who and when).
- **Activity**: the newest 50 workspace revisions with actor, op count or restored revision, and age.
- **Logs**: the server's last 200 console lines; warnings and errors are highlighted.

It polls `GET /api/status` every second with the token in `~/.ndea/mcp-token`; the endpoint answers 401 without it. The JSON also lists embedding load state and clients (open browser tabs, MCP requests in flight, agents by their `X-Ndea-Agent` header). Press `o` to open the dashboard, `c` to copy its URL, and `q` to quit. A non-terminal stdout prints the Overview as plain text. `ndea view` shows the same screen in a terminal, where `q` or Ctrl+C stops the server and console output goes to the Logs tab instead of over the screen.

| Option          | Env         | Default     | Description                                       |
| --------------- | ----------- | ----------- | ------------------------------------------------- |
| `--json`        |             | `false`     | Print one `/api/status` snapshot as JSON and exit |
| `--host <host>` | `NDEA_HOST` | `127.0.0.1` | Host of the running server                        |
| `--port <port>` | `NDEA_PORT` | `5055`      | Port of the running server                        |

## `ndea workspace`

Read, edit, and query the workspace document of a running `ndea view` server. Edits go through the same validated path as the browser, and open browser tabs update live.

Every subcommand prints the server's JSON to stdout. When the server rejects a request, its response body goes to stderr verbatim and the command exits 1; an unreachable server is reported on stderr, also with exit 1.

| Option          | Env         | Default     | Description                |
| --------------- | ----------- | ----------- | -------------------------- |
| `--host <host>` | `NDEA_HOST` | `127.0.0.1` | Host of the running server |
| `--port <port>` | `NDEA_PORT` | `5055`      | Port of the running server |

A flag beats its environment variable, which beats the default. `ndea mcp check` takes the same two; `ndea mcp install` takes `--port` / `NDEA_PORT`.

```bash
ndea workspace get
ndea workspace patch --revision 3 --ops '[{"op":"replace","path":"/layouts/exploration/spec/elements/root/props/ratio","value":0.6}]'
```

`get` prints `{ "revision", "document" }`. `patch` applies [RFC 6902](https://www.rfc-editor.org/rfc/rfc6902) operations to the document at `--revision` and prints the new `{ "revision" }`. Read the revision with `get` first.

`patch` exits 1 with the response body on stderr when:

- `--revision` is stale: the body carries the current `revision` and `document` to rebase onto.
- The result is invalid: the body is an [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) problem whose `errors[].pointer` locates each issue, and nothing is saved.

`history` prints `{ "revisions" }`, newest first (`--limit`, default 50, at most 500). Each revision carries `revision`, `baseRevision`, `actor` (`kind`: `system` for the seed or a baseline, `browser`, `cli`, or `mcp` with the agent's `X-Ndea-Agent` name), the `ops` that produced it, `committedAt`, and `restoredFrom` when it restored an earlier revision. History lives in `<workspace>.history.sqlite` beside the workspace file and survives restarts.

`restore` commits the document at an earlier revision as a new revision; everything in between stays in history. It applies against the current revision, or against `--base` if given, and fails like `patch` when that base is stale or the restored document no longer validates (for example, it names a deleted set). `GET /api/workspace/revisions/<n>` prints one revision's `{ "revision", "document" }`.

```bash
ndea workspace history --limit 5
ndea workspace restore 1
```

`result` evaluates one dashboard element, or one data source with `--data`, at the current revision and prints `{ "revision", "predicate", "count" }`:

```bash
ndea workspace result table
ndea workspace result --data infected
```

- `predicate` is the SQL the element shows: its data source AND the other members' clauses in its filter scope. `count` is exact.
- The result reflects the saved document. Lassos, chart brushes, picks, focus, and color-by are saved as coordination state, so the server sees them once the tab's edit lands (within about half a second).
- An unknown element or data source exits 1.

`query` runs a typed filter clause and prints the matching observations. The server compiles the clause with the same compiler as dashboard data sources and filter scopes, so both select the same observations.

```bash
ndea workspace query --where '{"op":"and","clauses":[{"op":"eq","column":"predicted_infection_state","value":"infected"},{"op":"between","column":"t","range":[0,5]}]}'
```

A clause is one of `eq`, `neq`, `lt`, `lte`, `gt`, `gte` (`column`, `value`), `between` (`column`, `range`), `in` (`column`, `values`), `isNull`/`isNotNull` (`column`), `and`/`or` (`clauses`), or `not` (`clause`). Raw SQL is not accepted.

The output has `sql` (the compiled WHERE fragment), `count` (exact), `rows` ordered by row index, and `truncated`. Each row carries `datasetKey` and `obsName`, the durable identity, plus `rowIndex`, the handle the other `/api` routes accept. Observation names can repeat across datasets, so use `datasetKey` and `obsName` together.

| Option           | Type    | Default  | Description                                     |
| ---------------- | ------- | -------- | ----------------------------------------------- |
| `--where <json>` | JSON    | all rows | Filter clause                                   |
| `--limit <n>`    | integer | `1000`   | Maximum rows to return; `count` is always exact |

`query` exits 1 when the clause is invalid JSON, fails validation, or references an unknown column.

The server executes observation predicates as prepared single SQL statements for lookups, annotation writes, and exports. Stacked statements are rejected before execution. Lassos use durable observation sets through `POST /api/sets`; each set shares the dataset's DuckDB connection so its filter also applies to annotations and exports.

Workspace patches reject unknown set references anywhere in the document. Startup checks the same references when restoring a workspace.

### The dashboard

`/layouts` maps layout ids to `{ "name", "spec" }`, and `/layout` is the id of the layout the browser shows. Each `spec` is a [json-render](https://json-render.dev) flat spec: `{ "root", "elements" }`, where every element has a `type`, `props`, and `children` (element ids). Every element is reachable from its layout's `root` exactly once, and element ids are unique across all layouts. `/data` and `/state` are shared by every layout.

| Type                                                                                                    | Props                                                                                             | Children    |
| ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ----------- |
| `split`                                                                                                 | `direction` (`row` or `column`), `ratio` (0.05 to 0.95, the first child's share)                  | exactly two |
| `stack`                                                                                                 | `direction`, `gap` (px)                                                                           | any number  |
| `text`                                                                                                  | `text` (a string or `{"$template": "…${/focus/A}"}`), `variant` (`heading`, `body`, `muted`)      | none        |
| `select`                                                                                                | `column`, optional `label`; picking values publishes `{"op":"in"}` into its filter scope          | none        |
| `tabs`                                                                                                  | `active`: the id of the child the tile shows                                                      | one or more views |
| `slot`                                                                                                  | none: an empty tile                                                                               | none        |
| `scatter`, `table`, `count`, `count-plot`, `histogram`, `vgplot`, `gallery`, `image-viewer` | the view's own settings, such as `columns` and `groupBy` for `table` or `entries` and `attributes` for `vgplot` | none        |

Every component that reads observations also accepts `data` (the name of a data source; omitted means every observation) and `title`. `count` is the metric: the live number of rows its data and filter scope select. `vgplot` props are a [Mosaic](https://idl.uw.edu/mosaic) plot spec: `entries` is the `plot` array of marks and interactors, `attributes` the rest, with `$table`, `$scope` (the element's predicate), and `$brush` (a selection the chart publishes as a typed clause) supplied by the host.

`/data` maps names to sources: `{ "from"?, "where"?, "sql"? }`. A source narrows `from` (another source, or every observation) by a typed `where` clause (the `ndea workspace query --where` shape, including `{"op":"inSet","set":"<id>"}` for a saved selection) and/or a `sql` predicate.

```bash
# A data source, and a metric reading it beside the scatter plot's tile.
ndea workspace patch --revision 7 --ops '[
  {"op":"add","path":"/data/infected","value":{"where":{"op":"eq","column":"predicted_infection_state","value":"infected"}}},
  {"op":"add","path":"/layouts/exploration/spec/elements/n-inf","value":{"type":"count","props":{"title":"Infected","data":"infected"},"children":[]}},
  {"op":"add","path":"/layouts/exploration/spec/elements/left","value":{"type":"split","props":{"direction":"column","ratio":0.2},"children":["n-inf","embedding"]}},
  {"op":"replace","path":"/layouts/exploration/spec/elements/top/children/0","value":"left"}
]'
```

A view on its own is a tile with one tab; a `tabs` element is a tile with several. A patch is rejected with the offending pointer when it leaves an element unreachable, gives a split other than two children, puts anything but views in `tabs` or names a missing `active` tab, reuses an element id from another layout, names an unknown component or data source, or sets a prop the component's schema refuses, for example `/layouts/exploration/spec/elements/table/props/columns`. MCP `edit_dashboard` has named ops for layouts and tabs, so agents rarely need these paths.

### Linking views

Elements link through coordination state, so an agent links and drives them with plain patches. A prop `{"$bindState": "/<type>/<scope>"}` (json-render's two-way binding) joins an element to a scope; `/state/<type>/<scope>` holds the shared value. Types are `focus` (a row index or `null`), `filter`, `colorBy` (a column name or `null`), `viewSync`, and `ordering`.

```bash
# Put the metric in filter scope A (the scope must exist in state first).
ndea workspace patch --revision 8 --ops '[
  {"op":"add","path":"/layouts/exploration/spec/elements/n-inf/props/filter","value":{"$bindState":"/filter/A"}}
]'
# Filter every member of scope A to infected cells, as the source "agent".
ndea workspace patch --revision 9 --ops '[
  {"op":"add","path":"/state/filter/A/agent","value":{"where":{"op":"eq","column":"infected","value":true}}}
]'
# Focus row 812 in every view on focus scope A.
ndea workspace patch --revision 10 --ops '[{"op":"replace","path":"/state/focus/A","value":812}]'
```

A filter scope maps each source (an element id, or an agent's own key) to named clauses, using the same clause shape as `ndea workspace query --where`. Each member sees every other source's clauses, never its own, so a scatter lasso filters the table but not the scatter. Lassos appear as `{"op":"inSet","set":"<id>"}`, which refers to an observation set saved under `~/.ndea/sets/`. A patch that refers to an unknown set is rejected.

## MCP server

A running `ndea view` serves the [Model Context Protocol](https://modelcontextprotocol.io) over Streamable HTTP at `/mcp` on the same port, so an agent (the harness) edits the workspace you have open. Every accepted edit appears in the browser without a reload.

The endpoint answers only localhost `Host` and `Origin` headers and requires the bearer token in `~/.ndea/mcp-token`, created on first use with owner-only permissions. The token survives restarts, so you connect each agent once.

```bash
ndea mcp install                           # pick from the agents detected on this machine
ndea mcp install --agent claude-code,codex  # no prompt; --yes installs to every detected agent
ndea mcp check                             # server up? token accepted? which agents are current?
ndea mcp uninstall                         # remove ndea from every agent that has it
```

`install` writes `http://127.0.0.1:<port>/mcp`, the token, and an `X-Ndea-Agent: <agent>` header into each agent's own config through [add-mcp](https://add-mcp.com), which knows the format of Claude Code, Codex, Cursor, VS Code, Zed, OpenCode, and 16 more. Restart open agent sessions afterwards. Pass `--port` (or set `NDEA_PORT`) to `install` and `check` when `ndea view` runs on another port. `check` exits 1 when the server is down, rejects the token, or an agent still has an old token or port.

Agent writes appear in workspace history as `mcp` with the `X-Ndea-Agent` name (letters, digits, `_`, `.`, `-`; up to 64 characters; anything else is dropped). The name is a label, not a credential: the token is what grants access. To label a hand-written config, add the header next to `Authorization`, for example `"X-Ndea-Agent": "omp"`.

| Tool                     | Does                                                                                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `get_workspace`          | The whole document: data sources, layouts (each a dashboard spec) and the active one, and coordination state, with its revision                       |
| `list_components`        | Every component with its description, children rule, whether it reads data, the scopes it can bind, defaults, and JSON Schema                           |
| `list_columns`           | Observation columns with their types and kind (obs, var, annotation); pass `column` for distinct count, range, and its most frequent values             |
| `list_collections`       | The project's collections (each with its datasets and obs counts) and the open one                                                                      |
| `get_result`             | One element's or data source's predicate and exact count                                                                                                |
| `edit_dashboard`         | Named ops: `set_data`, `remove_data`, `add` (into a slot, a stack, or beside an element, in any layout), `set_props`, `remove`, `swap`, `bind`, `unbind`, `set_filter`; tabs: `add_tab`, `move_tab`, `close_tab`, `set_active_tab`; layouts: `add_layout` (blank or a copy), `rename_layout`, `remove_layout`, `set_active_layout`. Proposes them while Harness edits are set to Propose |
| `get_proposal`           | One proposal's changes with their status: pending, accepted, rejected, or invalid (with the reason it no longer applied)                                |
| `patch_workspace`        | Raw RFC 6902 ops at an exact revision, for anything the named ops do not cover; only when Harness edits are set to Apply directly                       |
| `get_history`            | Recent revisions, newest first: who committed each (actor and agent), its ops, time, and `restoredFrom`                                                 |
| `restore_revision`       | Commit an earlier revision's document as a new revision; `revision_base` applies only if the workspace is still at that revision. Apply directly only  |
| `create_observation_set` | Save an element's, a data source's, or a clause's rows as a set for `{"op":"inSet"}` clauses                                                            |

`edit_dashboard` validates a whole batch, and refuses all of it if any op fails. Pass `revision` to act only if the workspace has not changed since you read it. Every write, from the browser, the CLI, or an agent, is checked like a document load: structure, component props, data references, bindings, and set references. A refused edit names the op or document path to fix and changes nothing.

### Proposals

You review harness edits. By default (Settings › Harness edits: **Propose**), `edit_dashboard` returns `{ "status": "proposed", "id", "changes": [{ "index", "summary" }] }` instead of a revision: each change waits as a proposal until you accept or reject it, and the agent reads the outcome with `get_proposal`. `set_filter` ops still apply at once, since filters are exploration state, not layout or source edits; a batch that mixes them applies its filters and proposes the rest. Accepting re-runs the chosen changes against the current workspace and commits them as one revision recorded under the agent's name; a change that no longer applies (say, the view it targets is gone) becomes invalid with its reason while the others still commit. `patch_workspace` and `restore_revision` are refused in Propose mode. **Apply directly** makes agent edits take effect immediately, as before. Proposals live in the server's memory: restarting `ndea view` drops pending ones.

In the browser, a proposed tile shows as a ghost tile with Accept / Reject; other changes (sources with a before → after diff, props, removals, links, layouts) are listed in a bar at the bottom with Accept all / Reject all, and in the Harness flyout with the tool-call feed. Settings › Harness edits switches between Propose and Apply directly. A rejected edit shows once as a toast.

The same state is available over HTTP: `GET /api/harness` (agents, mode, pending proposals, and the last 50 tool calls), `PUT /api/harness/mode` with `{ "mode": "propose" | "direct" }`, and `POST /api/proposals/<id>/accept` or `/reject` with an optional `{ "changes": [<index>, …] }` (default: every pending change).

## `ndea completion`

Print a static shell completion script for `bash`, `zsh`, or `fish`. Scripts list every command, flag, and choice; `view` paths fall back to the shell's file completion. They do not call `ndea` on Tab.

```bash
# Bash, in ~/.bashrc
source <(ndea completion bash)

# Zsh, after compinit in ~/.zshrc
source <(ndea completion zsh)

# Fish, in ~/.config/fish/config.fish
status --is-interactive; and ndea completion fish | source
```

Open a new shell after `ndea self update` to pick up new commands and flags.

## `ndea man`

Print ndea's manual page as mdoc, generated from the same command definitions as `--help`:

```bash
ndea man | man -l -     # Linux
ndea man | mandoc -a    # macOS
```

## Release channels

| Channel       | Resolves to                                  | Cadence                                                    |
| ------------- | -------------------------------------------- | ---------------------------------------------------------- |
| `stable`      | latest semver-tagged release (e.g. `v0.1.0`) | Manual; cut from `main` when ready                         |
| `latest`      | alias for `stable`                           | Same as `stable`                                           |
| `pre-release` | newest published alpha / beta / rc release   | Manual; unavailable until a pre-release has been published |

`stable` and `latest` use GitHub's latest release. `pre-release` selects the newest published, non-draft semver pre-release. `ndea self update` resolves the channel through the public GitHub Releases API at update time.

## State directory layout

`~/.ndea/`:

```
~/.ndea/
  current-version              # Plain text: "<tag>\n<sha256>\n"
  versions/
    v0.1.0/
      ndea                     # bun-compiled binary (DuckDB linked in on macOS arm64)
    v0.1.1/
      …
  locks/
    install.lock               # PID file backing the install/update mutex
  workspaces/
    <key>.json                 # Default workspace document per set of datasets
    <key>.history.sqlite       # Its revision history (actor, ops, document per revision)
  mcp-token                    # Bearer token for /mcp (owner-only)
~/.cache/ndea/
  0.1.0/
    libduckdb.{dylib,so}       # Linux and macOS x64 only: extracted on first launch
    v0.2.0-v1.5.6-<platform>/
      zarr.duckdb_extension    # duckdb-zarr, which reads every dataset: extracted on first launch
  ingest/
    <key>.duckdb               # Ingested obs/var per local project, reused on the next start
```

On macOS arm64, DuckDB is statically linked into the binary, so nothing is extracted and the binary is about 132 MB. On Linux and macOS x64 it embeds `libduckdb` (about 200 MB) and extracts it on first launch. Every platform embeds the duckdb-zarr extension (about 7 MB) and extracts it on first launch; `LOAD` reads that local file, so no network is needed. `ndea self prune` also removes version-scoped native-library caches corresponding to pruned releases.

`~/.local/bin/ndea` points to the active binary under `~/.ndea/versions/<tag>/ndea`.

On Windows the layout is flat, with no versions tree and no symlink:

```
%LOCALAPPDATA%\ndea\
  bin\
    ndea.exe                   # On PATH via a user environment entry
  0.1.0\
    duckdb.dll                 # Extracted from the binary on first launch
    v0.2.0-v1.5.6-windows_amd64\
      zarr.duckdb_extension    # Extracted from the binary on first launch
%USERPROFILE%\.ndea\
  current-version              # Plain text: "<tag>\n<sha256>"
```

DuckDB ships the Windows library as `duckdb.dll` rather than `libduckdb.dll`. Because only one version is ever installed, `ndea self prune` has nothing to prune.

This page lists the supported `ndea` commands, flags, and release channels.

Walkthroughs live in [Getting started](/). Dev-side commands (`vp run dev`, `vp run gen`, …) live in [Contributing](/contributing).

## Synopsis

```
ndea [paths...]                                  # default; equivalent to `ndea view`
ndea view [paths...] [options]
ndea update [options]
ndea gc [options]
ndea doctor [--check-network] [--strict]
ndea filter [--where <json>] [--limit <n>] [--host <host>] [--port <port>]
ndea workspace get [--host <host>] [--port <port>]
ndea workspace patch --revision <n> --ops <json> [--host <host>] [--port <port>]
ndea workspace result <element> | --data <name> [--host <host>] [--port <port>]
ndea completions <bash|zsh|fish>
ndea complete -- <args...>                       # internal; called by completion scripts
ndea --help | --version
```

## Shorthand

`ndea path/to/data.zarr` is equivalent to `ndea view path/to/data.zarr`.

## `ndea view`

Open one or more Zarr stores, or a YAML project config, in ndea.

### Arguments

| Name     | Type              | Description                                 |
| -------- | ----------------- | ------------------------------------------- |
| `paths…` | one or more paths | Zarr stores or a single YAML project config |

A single `.yaml` / `.yml` path is parsed as a multi-dataset project config (see [Project YAML](/project-config)).

### Options

| Option                 | Type    | Default     | Description                                                                         |
| ---------------------- | ------- | ----------- | ----------------------------------------------------------------------------------- |
| `--port <port>`        | integer | `5055`      | TCP port for the local server                                                       |
| `--host <host>`        | string  | `127.0.0.1` | Hostname to bind                                                                    |
| `--no-open`            | boolean | `false`     | Do not auto-open the browser                                                        |
| `--no-static`          | boolean | `false`     | Do not serve the bundled frontend (Vite serves it in dev mode)                      |
| `--obs-columns <list>` | string  | all columns | Comma-separated subset of obs columns to load                                       |
| `--preset <name>`      | string  | `annotate`  | Preset a new workspace file starts from: `annotate` or a `.json` workspace document |
| `--workspace <file>`   | path    | see below   | Workspace document to open and save                                                 |

### Workspace file

The running server owns one workspace document: named data sources, the dashboard spec, and coordination state. Every edit, from the browser or from `ndea workspace patch`, is saved to the workspace file as a new revision. Without `--workspace`, ndea uses `~/.ndea/workspaces/<key>.json`, where the key is derived from the dataset paths, so opening the same datasets reopens the same workspace. A missing file is written from the preset as revision 1, before any browser opens. A preset is itself a workspace document: `--preset annotate` uses the built-in one, and `--preset my-layout.json` copies any valid document, such as the `document` field printed by `ndea workspace get`. A file or preset that fails validation stops `ndea view` before any data loads and lists each problem by JSON Pointer; ndea never rewrites or migrates it.

`--port` accepts integers in `[1, 65535]`.

## `ndea update`

Download and activate the latest release for a channel. ndea verifies the SHA-256 checksum before switching versions.

Not available on Windows. Windows installs are a single `ndea.exe` with no versions tree and no symlink to swap, so the command exits with an error; re-run `install.ps1` to move to a newer release.

### Options

| Option                | Type                                  | Default  | Description                                                 |
| --------------------- | ------------------------------------- | -------- | ----------------------------------------------------------- |
| `--channel <channel>` | `stable` \| `latest` \| `pre-release` | `stable` | Release channel to resolve                                  |
| `--force`             | boolean                               | `false`  | Re-install even when already on the target                  |
| `--no-gc`             | boolean                               | `false`  | Skip the post-update auto-gc that removes inactive versions |

For standalone installs, a successful update keeps only the active version by default. Pass `--no-gc` to retain inactive versions, then prune them later with `ndea gc`.

For mise-managed installs, `ndea update` updates the active mise config through mise and does not write to `~/.ndea/versions`. `--no-gc` has no effect because mise owns version retention.

A running `ndea view` session continues using the version it started with.

To install a specific older standalone release, uninstall the current standalone installation, then pass its tag to the installer:

```bash
rm -f "$HOME/.local/bin/ndea"
rm -rf "$HOME/.ndea"
curl -fsSL https://czbiohub-sf.github.io/nd-embedding-atlas/install.sh | sh -s -- v0.1.0
```

On Windows, pass the tag to the installer; it replaces `ndea.exe` in place, so no removal step is needed:

```powershell
& ([scriptblock]::Create((irm https://czbiohub-sf.github.io/nd-embedding-atlas/install.ps1))) -Version v0.1.0
```

For mise-managed installs, select a version explicitly:

```bash
mise use -g --pin github:czbiohub-sf/nd-embedding-atlas@0.1.0
```

## `ndea gc`

Prune old installed versions. ndea always preserves the active version.

### Options

| Option       | Type    | Default | Description                                       |
| ------------ | ------- | ------- | ------------------------------------------------- |
| `--keep <N>` | integer | `1`     | Number of versions to keep (active counts; min 1) |

## `ndea doctor`

Diagnose the install. Prints binary path, symlink integrity, active version, installed versions with disk usage. Exit code 0 if healthy, 1 on hard anomalies (broken symlink, missing active binary).

On Windows the symlink and installed-versions sections are omitted, because that layout has neither. Everything else, including the extracted-library cache check, reports normally.

### Options

| Option            | Type    | Default | Description                                                           |
| ----------------- | ------- | ------- | --------------------------------------------------------------------- |
| `--check-network` | boolean | `false` | Probe GitHub Releases API reachability over the network (3 s timeout) |
| `--strict`        | boolean | `false` | Treat warnings as errors (non-zero exit)                              |

## `ndea filter`

Filter observations on a running `ndea view` server and print the matches as JSON. The server compiles the clause with the same compiler as dashboard data sources and filter scopes, so both select the same observations.

```bash
ndea filter --where '{"op":"and","clauses":[{"op":"eq","column":"predicted_infection_state","value":"infected"},{"op":"between","column":"t","range":[0,5]}]}'
```

A clause is one of `eq`, `neq`, `lt`, `lte`, `gt`, `gte` (`column`, `value`), `between` (`column`, `range`), `in` (`column`, `values`), `isNull`/`isNotNull` (`column`), `and`/`or` (`clauses`), or `not` (`clause`). Raw SQL is not accepted.

The output has `sql` (the compiled WHERE fragment), `count` (exact), `rows` ordered by row index, and `truncated`. Each row carries `datasetKey` and `obsName`, the durable identity, plus `rowIndex`, the handle the other `/api` routes accept. Observation names can repeat across datasets, so use `datasetKey` and `obsName` together.

### Options

| Option           | Type    | Default     | Description                                     |
| ---------------- | ------- | ----------- | ----------------------------------------------- |
| `--where <json>` | string  | all rows    | Filter clause as JSON                           |
| `--limit <n>`    | integer | `1000`      | Maximum rows to return; `count` is always exact |
| `--host <host>`  | string  | `127.0.0.1` | Host of the running server                      |
| `--port <port>`  | integer | `5055`      | Port of the running server                      |

Exits 1 when the clause is invalid JSON, fails validation, references an unknown column, or no server is reachable. The error body goes to stderr.

## `ndea workspace`

Read and edit the workspace document of a running `ndea view` server. Edits go through the same validated path as the browser, and open browser tabs update live.

```bash
ndea workspace get
ndea workspace patch --revision 3 --ops '[{"op":"replace","path":"/spec/elements/root/props/ratio","value":0.6}]'
```

`get` prints `{ "revision", "document" }`. `patch` applies [RFC 6902](https://www.rfc-editor.org/rfc/rfc6902) operations to the document at `--revision` and prints the new `{ "revision" }`. Read the revision with `get` first.

`patch` exits 1 with the response body on stderr when:

- `--revision` is stale: the body carries the current `revision` and `document` to rebase onto.
- The result is invalid: the body is an [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) problem whose `errors[].pointer` locates each issue, and nothing is saved.

`result` evaluates one dashboard element, or one data source with `--data`, at the current revision and prints `{ "revision", "predicate", "count" }`:

```bash
ndea workspace result table
ndea workspace result --data infected
```

- `predicate` is the SQL the element shows: its data source AND the other members' clauses in its filter scope. `count` is exact.
- The result reflects the saved document. Lassos, chart brushes, picks, focus, and color-by are saved as coordination state, so the server sees them once the tab's edit lands (within about half a second).
- An unknown element or data source exits 1.

The server executes observation predicates as prepared single SQL statements for lookups, annotation writes, and exports. Stacked statements are rejected before execution. Lassos use durable observation sets through `POST /api/sets`; each set shares the dataset's DuckDB connection so its filter also applies to annotations and exports.

Workspace patches reject unknown set references anywhere in the document. Startup checks the same references when restoring a workspace.

### The dashboard

`/spec` is a [json-render](https://json-render.dev) flat spec: `{ "root", "elements" }`, where every element has a `type`, `props`, and `children` (element ids). Every element is reachable from `root` exactly once.

| Type                                                                                                    | Props                                                                                             | Children    |
| ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ----------- |
| `split`                                                                                                 | `direction` (`row` or `column`), `ratio` (0.05 to 0.95, the first child's share)                  | exactly two |
| `stack`                                                                                                 | `direction`, `gap` (px)                                                                           | any number  |
| `text`                                                                                                  | `text` (a string or `{"$template": "…${/focus/A}"}`), `variant` (`heading`, `body`, `muted`)      | none        |
| `select`                                                                                                | `column`, optional `label`; picking values publishes `{"op":"in"}` into its filter scope          | none        |
| `slot`                                                                                                  | none: an empty tile                                                                               | none        |
| `scatter`, `table`, `count`, `count-plot`, `histogram`, `vgplot`, `gallery`, `image-viewer`, `annotate` | the view's own settings, such as `columns` for `table` or `entries` and `attributes` for `vgplot` | none        |

Every component that reads observations also accepts `data` (the name of a data source; omitted means every observation) and `title`. `count` is the metric: the live number of rows its data and filter scope select. `vgplot` props are a [Mosaic](https://idl.uw.edu/mosaic) plot spec: `entries` is the `plot` array of marks and interactors, `attributes` the rest, with `$table`, `$scope` (the element's predicate), and `$brush` (a selection the chart publishes as a typed clause) supplied by the host.

`/data` maps names to sources: `{ "from"?, "where"?, "sql"? }`. A source narrows `from` (another source, or every observation) by a typed `where` clause (the `ndea filter --where` shape, including `{"op":"inSet","set":"<id>"}` for a saved selection) and/or a `sql` predicate.

```bash
# A data source, and a metric reading it beside the scatter plot's tile.
ndea workspace patch --revision 7 --ops '[
  {"op":"add","path":"/data/infected","value":{"where":{"op":"eq","column":"predicted_infection_state","value":"infected"}}},
  {"op":"add","path":"/spec/elements/n-inf","value":{"type":"count","props":{"title":"Infected","data":"infected"},"children":[]}},
  {"op":"add","path":"/spec/elements/top","value":{"type":"split","props":{"direction":"column","ratio":0.2},"children":["n-inf","scatter"]}},
  {"op":"replace","path":"/spec/elements/root/children/0","value":"top"}
]'
```

A patch is rejected with the offending pointer when it leaves an element unreachable, gives a split other than two children, names an unknown component or data source, or sets a prop the component's schema refuses, for example `/spec/elements/table/props/columns`.

### Linking views

Elements link through coordination state, so an agent links and drives them with plain patches. A prop `{"$bindState": "/<type>/<scope>"}` (json-render's two-way binding) joins an element to a scope; `/state/<type>/<scope>` holds the shared value. Types are `focus` (a row index or `null`), `filter`, `colorBy` (a column name or `null`), `viewSync`, and `ordering`.

```bash
# Put the metric in filter scope A (the scope must exist in state first).
ndea workspace patch --revision 8 --ops '[
  {"op":"add","path":"/spec/elements/n-inf/props/filter","value":{"$bindState":"/filter/A"}}
]'
# Filter every member of scope A to infected cells, as the source "agent".
ndea workspace patch --revision 9 --ops '[
  {"op":"add","path":"/state/filter/A/agent","value":{"where":{"op":"eq","column":"infected","value":true}}}
]'
# Focus row 812 in every view on focus scope A.
ndea workspace patch --revision 10 --ops '[{"op":"replace","path":"/state/focus/A","value":812}]'
```

A filter scope maps each source (an element id, or an agent's own key) to named clauses, using the same clause shape as `ndea filter --where`. Each member sees every other source's clauses, never its own, so a scatter lasso filters the table but not the scatter. Lassos appear as `{"op":"inSet","set":"<id>"}`, which refers to an observation set saved under `~/.ndea/sets/`. A patch that refers to an unknown set is rejected.

All three subcommands accept `--host` (default `127.0.0.1`) and `--port` (default `5055`).

## MCP server

A running `ndea view` serves the [Model Context Protocol](https://modelcontextprotocol.io) over Streamable HTTP at `/mcp` on the same port, so an agent edits the workspace you have open. Every accepted edit appears in the browser without a reload.

The endpoint answers only localhost `Host` and `Origin` headers and requires the bearer token in `~/.ndea/mcp-token`, created on first use with owner-only permissions. The token survives restarts, so you connect each agent once.

```bash
ndea mcp install                           # pick from the agents detected on this machine
ndea mcp install --agent claude-code,codex  # no prompt; --yes installs to every detected agent
ndea mcp check                             # server up? token accepted? which agents are current?
ndea mcp uninstall                         # remove ndea from every agent that has it
```

`install` writes `http://127.0.0.1:<port>/mcp` and the token into each agent's own config through [add-mcp](https://add-mcp.com), which knows the format of Claude Code, Codex, Cursor, VS Code, Zed, OpenCode, and 16 more. Restart open agent sessions afterwards. Pass `--port` to all three commands when `ndea view` runs on another port. `check` exits 1 when the server is down, rejects the token, or an agent still has an old token or port.

| Tool                     | Does                                                                                                                                                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `get_workspace`          | The whole document: data sources, dashboard spec, and coordination state, with its revision                                                             |
| `list_components`        | Every component with its description, children rule, whether it reads data, the scopes it can bind, defaults, and JSON Schema                           |
| `list_columns`           | Observation columns and types; pass `column` for distinct count, range, and its most frequent values                                                    |
| `get_result`             | One element's or data source's predicate and exact count                                                                                                |
| `edit_dashboard`         | Named ops: `set_data`, `remove_data`, `add` (into a slot, a stack, or beside an element), `set_props`, `remove`, `swap`, `bind`, `unbind`, `set_filter` |
| `patch_workspace`        | Raw RFC 6902 ops at an exact revision, for anything the named ops do not cover                                                                          |
| `create_observation_set` | Save an element's, a data source's, or a clause's rows as a set for `{"op":"inSet"}` clauses                                                            |

`edit_dashboard` applies a whole batch or nothing. Pass `revision` to apply only if the workspace has not changed since you read it. Every write, from the browser, the CLI, or an agent, is checked like a document load: structure, component props, data references, bindings, and set references. A refused edit names the op or document path to fix and changes nothing.

## `ndea completions`

Emit shell completion scripts.

### Arguments

| Name  | Type                      | Description       |
| ----- | ------------------------- | ----------------- |
| shell | `bash` \| `zsh` \| `fish` | Shell to emit for |

### Usage

```bash
# bash / zsh: load on demand
source <(ndea completions bash)
source <(ndea completions zsh)

# fish: drop into the completions dir
ndea completions fish > ~/.config/fish/completions/ndea.fish
```

`view`'s positional completion filters to `*.zarr` directories and `*.yaml` / `*.yml` files.

## Release channels

| Channel       | Resolves to                                  | Cadence                                                    |
| ------------- | -------------------------------------------- | ---------------------------------------------------------- |
| `stable`      | latest semver-tagged release (e.g. `v0.1.0`) | Manual; cut from `main` when ready                         |
| `latest`      | alias for `stable`                           | Same as `stable`                                           |
| `pre-release` | newest published alpha / beta / rc release   | Manual; unavailable until a pre-release has been published |

`stable` and `latest` use GitHub's latest release. `pre-release` selects the newest published, non-draft semver pre-release. `ndea update` resolves the channel through the public GitHub Releases API at update time.

## State directory layout

`~/.ndea/`:

```
~/.ndea/
  current-version              # Plain text: "<tag>\n<sha256>\n"
  versions/
    v0.1.0/
      ndea                     # bun-compiled binary (~185 MB, embeds libduckdb)
    v0.1.1/
      …
  locks/
    install.lock               # PID file backing the install/update mutex
  workspaces/
    <key>.json                 # Default workspace document per set of datasets
  mcp-token                    # Bearer token for /mcp (owner-only)
~/.cache/ndea/
  0.1.0/
    libduckdb.{dylib,so}       # Extracted from the binary on first launch
```

A compiled version takes about 185 MB. `ndea gc` also removes version-scoped native-library caches corresponding to pruned releases.

`~/.local/bin/ndea` points to the active binary under `~/.ndea/versions/<tag>/ndea`.

On Windows the layout is flat, with no versions tree and no symlink:

```
%LOCALAPPDATA%\ndea\
  bin\
    ndea.exe                   # On PATH via a user environment entry
  0.1.0\
    duckdb.dll                 # Extracted from the binary on first launch
%USERPROFILE%\.ndea\
  current-version              # Plain text: "<tag>\n<sha256>"
```

DuckDB ships the Windows library as `duckdb.dll` rather than `libduckdb.dll`. Because only one version is ever installed, `ndea gc` has nothing to prune.

# Frontend

Reference for `apps/ndea/src/frontend/` (`@/`), `packages/components/`, and
`packages/ui/`. The design source of truth is `design_handoff_ndea_shell/`
(README, `design-system/tokens/`, reference JSX, prototype); `docs/design-phase-log.md`
records what was built from it and what still differs.

## Design system

- Tokens live in `packages/ui/src/tokens.css` (light `:root`, dark `.dark`,
  dark is the default); `styles.css` maps them to utilities (`bg-surface`,
  `bg-card`, `bg-overlay`, `text-text-muted`, `ring-tile-ring`, `bg-d1..9`,
  `bg-scope-*`, the design type scale `text-2xs`…`text-2xl` with `text-ui` =
  12px, radii `rounded-sm/md/lg`, `shadow-(--shadow-popover)`,
  `animate-nd-in`). Type sizes go on `body`; `html` keeps the 16px rem that
  Tailwind spacing relies on.
- Fonts: Geist for UI, Geist Mono for data (ids, counts, field names).
- `@ndea/ui` controls: `IconButton` (size `md` = 26px with a tooltip),
  `Popover` + `popoverFrame`/`popoverRow` (the one pop-up frame), `Select`,
  `Combobox`, `Command`, `Dialog`, `Tabs`, `ToggleGroup variant="segmented"`
  (`Segmented` for one string choice), `Switch`, `Checkbox`, `nd-icons`, and
  `floating-controls` (`ControlGroup`, `ControlPopover`, `ControlRow`,
  `ControlHeading`: the control column floating over the embedding and the
  image viewer). Tooltips wait 500ms. Toasts are Sonner
  (`components/ui/sonner.tsx`).
- Named colormaps (catalog lookup, hex palettes, GPU LUTs) are
  `@ndea/ochre/palette`; `lib/color/ochre-palette.ts` adds picker order, the
  default categorical palette, and "tab10" as d3's Tableau10.
- The theme is a per-browser preference (`ThemeProvider`, `localStorage`), as
  is Settings › Provenance badges; workspace state never goes there.

## Shell

- `core/shell/Shell.tsx`: a 32px rail (Search ⌘K, Layouts, Data, Links,
  Harness, Settings, pin). Hovering opens a 312px flyout over the tiles; click
  or ⌘B pins it and it pushes the grid. Flyouts live in `flyouts.tsx`.
- ⌘K (`CommandMenu.tsx`, on `@ndea/ui` `command`): switches layouts (with a
  wireframe preview that follows the highlight) and collections › datasets (a
  dataset of the open collection is a `_dataset` clause under source `dataset`
  in filter scope `A`; another collection switches the session after a
  confirm); `>` lists commands. The recovery page offers commands only.
- No top bar, status bar, or revision UI.

## Tiles, tabs, layouts

- json-render renders the active layout's spec (`core/workspace/DashboardPane.tsx`).
  `core/workspace/dashboard.ts` holds the component catalog (`COMPONENTS`:
  `split`, `stack`, `tabs`, `text`, `select`, `slot`, and one entry per view
  definition), structural and prop rules, layout lookups (`findElement`,
  `layoutOf`, `activeSpec`), `EMPTY_TILE_CHOICES`, and the pure edit operations.
- A tile is a bare view leaf (one tab) or a `tabs` element (`active` = shown
  child). The 30px header: tab strip (+ to add, × on multi-tab tiles), the
  embedding chip (embedding views), link indicator + popover
  (`LinksPopover.tsx`), view settings gear (`ViewSettings.tsx`, generated by
  `config-fields.ts`), copy reference (`reference.ts`), fullscreen. Right-click
  the header to split or remove. Dragging a tab onto another tile's strip
  moves it; onto a tile body swaps tiles. Layout editing ships in every build.
- Components get their element id through a render-only `elementId` prop;
  props resolve json-render expressions against coordination `state`.

## State and runtime

- `WorkspaceStore` (`core/workspace/workspace-store.ts`): every document write
  goes through `commit`; `apply(edits)` runs named ops; remote revisions arrive
  through `applyDocument`. Views ask it questions (`element(id)`,
  `elementPredicate(id)`, `coordination.filterFacet`/`setFilterFacet`/
  `stateStore`) rather than reading document shape; `WorkspaceSync`, the
  flyouts, and json-render read `snapshot()`. Editor-only state (selection,
  fullscreen, highlighted tiles) is `WorkspaceSession`.
- `WorkspaceSync` diffs `snapshot()` against the acknowledged revision and
  PATCHes it; a 409 or a remote revision rebases pending ops.
- `ComponentRuntimeManager` (`core/component/runtime/workspace-runtime.ts`)
  keeps one live body per view in a stable dock that tiles adopt, so moving a
  tile or tab never remounts it. Inactive tabs start on first show and stay
  alive; views outside the active layout stop and restart on switch. A config
  change from another writer restarts the body; the body's own `patchConfig`
  does not.
- `createComponentHost` (`core/component/runtime/host.ts`) builds the
  `ComponentHost`; `predicate` is the element's source AND its filter scope.
  Views query through `host.data.coordinator`. A row selection becomes a
  filter through `host.filter.publishSelection(facet, bits, rows, signal)`
  (creates the observation set, publishes `{ op: "inSet" }`, clears on
  `null`; an aborted signal publishes nothing). `DatasetSessionProvider` owns
  metadata, trajectories, and query infrastructure; its `refreshMetadata`
  (after every field write) also refetches the column catalog.
- Columns: every list of columns (table fields, chart/vgplot pickers, scatter
  color by) comes from the catalog, `useColumns()` / `fetchColumns()` in
  `packages/components/src/query/columns.ts` (`GET /api/columns`), never
  `DESCRIBE`. Mosaic glue (`toRows`, `filterExprToExpr`, `predicateToSql`,
  `usePredicateSql`, `stringPredicate`) lives once in `query/mosaic.ts`.
- A data component reads `props.data` (a named source; omitted = every obs).

## Proposals UI

`core/proposals/`: `useHarness` (`harness.ts`) holds the `harness/watch` state,
toasts each `rejected` push, and shakes the Harness rail button.
`previewProposals` (`preview.ts`, pure) applies pending `add` changes that open
a tile in the active layout to a copy of the document; the grid renders that
copy with those tiles as ghost tiles. Every other change is listed in the
proposal bar (bottom centre) and the Harness flyout. Accept/Reject call
`POST /api/proposals/:id/{accept,reject}`; the document follows through
`workspace/watch`.

## Embedding view (`packages/components/src/scatter/`)

- TypeGPU render core in `gpu/gpu/`: SoA positions (`/api/scatter-positions`
  sends the element's `xDim`/`yDim`/`zDim` columns of `obsmKey`), one
  `project()` for every pass, compaction + `drawIndirect`, a density splat when
  too many points are visible, GPU box/lasso on projected positions.
  `camera.ts` has `PanZoom2D` and `Turntable3D`; 3D `viewSync` cells carry
  `yaw/pitch/distance/target/projection`.
- `scene.ts` stores points in Morton order with 256-point batches and bounds;
  setters, the selection bitmask, and picks speak row order
  (`writeLayer`/`layerToRows`/`perm` translate).
- Controls float in the view (`ScatterControls.tsx`, on `@ndea/ui`
  `floating-controls`): pointer/box/lasso (V/B/L, shift adds, ⌥ subtracts),
  Legend / Point size / Axes popovers, the bottom-right
  axis picker, the pinned legend, and the selection pill (count from
  `host.filter.publishSelection`, Invert, Save as source via
  `host.dataAPI.saveSource`, Clear). Selections combine CPU-side
  (`selection-bits.ts`) and publish `{ op: "inSet" }` on the `lasso` facet.
  Props `xDim`, `yDim`, `zDim`, `pointSize`, `legend`, `density.mode` persist
  through `patchConfig`.

## Table (`packages/components/src/table/`)

The field editor: toolbar (search, `Filter │ Sort │ Group │ Fields`,
Save/Discard, "Write fields to file…"), type glyphs and provenance markers
(from the catalog's `kind`: obs read-only, annotation fields editable), and
server-side pages, counts, and groups that bypass Mosaic's cache because edits
change values under the same SQL. Cell edits stay in a client buffer until Save
(`host.dataAPI.writeFieldValues`); field operations apply at once. The filter
builder publishes on the `filter` facet and row selection (an observation set,
via `publishSelection`) on the `selection` facet; the table narrows by its own
builder clauses, never by its selection. No keyboard shortcuts.

## Image viewer and charts

- Image viewer top-left overlay: Channels (visibility, named colormaps,
  contrast over the channel-stats log histogram, auto contrast) and View (T/Z,
  2D/3D, focus box, volume, local/remote render); scale bar bottom-right in the
  OME-Zarr axis unit; focus box in `--focus-mark`.
- `vgplot` renders its props (`entries`, `attributes`) as a Mosaic plot spec
  with host-supplied `$table`, `$scope`, `$brush`. Histogram and count plot are
  Mosaic-driven charts.

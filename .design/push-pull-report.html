01The problem

A node graph is a dependency DAG: source → transform → views. When something changes — a slider, a new edge, a lasso — you must recompute the affected nodes, but only those, and only if anyone is looking. Pure-eager recomputes views nobody watches and storms on every keystroke. Pure-lazy has no notion of "stale," so it either recomputes the whole chain every read or never knows a cache went bad. The fix every mature node tool converges on (Houdini, Blender geometry nodes, TouchDesigner — and our engine): push the dirt, pull the data.

02Push — propagate dirtiness, not values

markDirty(id) does three cheap things and computes nothing: (1) walk downstream, flag every transitive dependent dirty; (2) bump a monotonic epoch; (3) abort the prior epoch's AbortSignal so superseded async work can cancel. Edges carry SQL predicate strings, so marking a subtree dirty is just flipping booleans. A flush is then scheduled (we use requestAnimationFrame), so a burst of edits in one frame coalesces into a single recompute pass.

Coalescing in the demo: the Drag ×6 button bumps the epoch six times but schedules only one flush — six conceptual edits, one cook pass.

03Pull — cook on demand, upstream, lazily

pull(id) walks upstream. If a node is clean with a cached value, it stops and returns the cache — the Houdini "a clean node is a cache boundary" rule; its ancestors are never touched. If dirty, it recursively pulls its inputs, runs cook(inputs), stamps the result with the current epoch, marks itself clean, and returns. A per-sweep visited set means a shared upstream node cooks once per flush even when three sinks depend on it (and it guards against re-entry if a cook goes async).

04Where the halves meet — "who pulls"

Push marks dirty; pull does work. The bridge: only display-active sinks pull. A mounted, visible view registers as a sink and is pulled on every flush. Close it → it unregisters → its upstream transforms are never cooked. That kills the #1 over-cooking trap: editing a filter that feeds a closed panel costs nothing. In the demo, the sink chips are that registration.

05Why the epoch matters

The epoch is the staleness stamp. Synchronously you barely need it; the moment a cook awaits a server round-trip, you must know whether an arriving result belongs to the current epoch or a superseded one. Old-epoch results get dropped; the aborted signal lets the stale work cancel itself rather than race.

Single-file, no dependencies. The simulation re-implements markDirty / flush / pull with the same cache-boundary, per-sweep dedup, fan-in, epoch, and display-active-gating semantics as the production GraphEngine. Open question (design brief §2): a user-driven push like a scatter lasso vs. this pull-shaped model.
